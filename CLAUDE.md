# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

EcoSculptor is a Unity graduation project (CENG 408): a hex-tile ecosystem game where the player reshapes terrain and a food chain of animals, driven by Unity ML-Agents policies, reacts to it. The README only links a gameplay video; the project write-up lives in the GitHub wiki, which is a **separate git repo** (`https://github.com/ozgundogann/EcoSculptor-Graduation-Project.wiki.git`). Clone it outside this working tree.

## Environment

- Unity **6000.3.5f2** (Unity 6), URP 17.3, `com.unity.ml-agents` **2.0.2**. Open the folder in the Editor; there is no CLI build script. `Assembly-CSharp*.csproj` / `.sln` are generated by the Editor.
- There are no tests (`com.unity.test-framework` is installed but no test assemblies exist) and no lint config.
- Unity 6 API: code uses `Rigidbody.linearVelocity`, not `velocity`.
- `MainMenu.cs` loads scene build index 1 to play and 0 to return, so keep `Main Menu` / `Main Scene` in that order in Build Settings. `Ege 2`, `Emre`, `AssetScene`, `InGameSS_Scene` look like per-person or utility scenes (the `Assets/ML-Agents/Timers/*.json` files are named after them).

## Training the agents

Training is run from a terminal with the Python `mlagents` trainer against the Editor in Play mode. The original runs used Python `mlagents` **0.30.0** with the Unity package 2.0.1 (recorded in `results/Final_1.0/run_logs/training_status.json`); the local Unity 6 upgrade bumps the package to 2.0.2.

```
mlagents-learn <config.yaml> --run-id=<name>
```

Then press Play in the Editor. Output goes to `results/<run-id>/` (checkpoints, `<Behavior>.onnx`, `configuration.yaml`, `run_logs`). Exported `.onnx` models live in `Assets/Trainings/<name>/` and are assigned to a prefab's Behavior Parameters. **`Assets/Trainings/4.0` is the latest model set** (per the author). Folder names and file dates are not reliable for judging recency: `Final 2.1(en son yapilan)` ("the last one made") and `Final3.x` are older, and every file's mtime is just the checkout time.

Which config produced which model (recovered by fitting ONNX weight counts): `results/Final_1.x` and `Assets/Trainings/final` = 1×256 with small ray sensors (124/44/44 ray inputs); `Final 2.1` / `Final3.1` = 2×512, which matches the root `MultiTraining.yaml`; **`4.0` = 2×256 with 205/164/205 ray inputs (matches the current prefab sensors), and its config and logs are not in the repo**. The only complete three-agent TensorBoard log is `results/Final_1.3`.

`MultiTraining.yaml` defines one PPO config per behavior. The keys **must match the `Behavior Name` on the prefabs' Behavior Parameters**: `Preyanimal`, `Hunteranimal`, `Alphahunteranimal` (note the casing). Renaming a behavior on a prefab without renaming it in the yaml silently trains nothing.

## Architecture

Two systems that meet at `AnimalManager`:

**Terrain / player side** (`Assets/Scripts/Tiles`, `Managers`, `Economy`)
- `HexGrid`/`Hex`/`HexCoordinates` model the map. `SelectionManager` + `TileChanger` (fed by `PlayerInput`) let the player swap tile types (`TileTypeEnum`).
- `TileManager` keeps running counts per tile type (grass, water, river, sand, dirt, stone). Those counts are the game's ecological state.
- `EconomyManager` charges the player using ScriptableObject catalogs (`TilePriceCatalog`, `EatingPriceCatalog`, `DeathPriceCatalog`, assets sit next to the scripts) — tile changes are priced, and there are separate catalogs for animals eating and dying.
- `TimeManager`, `LightingManager` (day/night preset), `WinterHandler` handle time and seasons.

**Animal / ML side** (`Assets/Scripts/Animals`)
- Three `Agent` subclasses form the food chain: `PreyAnimal` (Deer, Horse) → `HunterAnimal` (Wolf, Tiger) → `AlphaHunterAnimal` (Bear). Prefabs are under `Assets/Prefabs/Animals/{Preys,Hunters/WeakestHunter,Hunters/AlfaHunters}`.
- Each agent has 2 continuous actions (rotate, move forward), observes `transform.localPosition` in code **plus** a `RayPerceptionSensorComponent3D` configured on the prefab, and is rewarded/penalised in `OnTriggerEnter` (tags such as `nectar`, `boundary`). `Hunger` is a separate component that fires `OnAnimalDeathByHunger`.
- The event-driven reward/episode logic (`OnEpisodeBegin`, `AddReward`, `EndEpisode` in the agents' `OnTriggerEnter`/`Eat*`/`RewardFood` methods) is **commented out**; the author confirmed those values are the training-time rewards (food +5, all food +15, catch +6/+5, caught −5, boundary −10). The one live reward is the 80 s timeout in `FoodManager.CheckRemainingTime` (−5 to each agent, ends episodes). Restore the commented blocks before retraining.
- `TrainingMap.prefab` and `DeerAreaController` are the training arena setup.
- `AnimalManager` (singleton) owns the per-species lists and spawns animals from `AnimalSpawnRules` based on `TileManager` counts (e.g. bears spawn when `StoneTile` reaches multiples of `stoneTileCountForBear` and total animal count is high enough). So changing terrain is how the player indirectly controls which animals exist.

Managers are all `MonoBehaviour` singletons via a static `Instance` set in `Awake`; cross-system calls go through `X.Instance`.
